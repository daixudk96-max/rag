树流程超简单版

现在系统做的事情很简单：
先把文档切成很多小纸条 → 再把小纸条装进几个盒子 → 用户提问时，去找最像的盒子 → 把盒子里的原文拿出来。

第 1 步

把一整份文档，切成很多小段小段的话。
你可以把它想成很多张小纸条。

→

第 2 步

看看哪些小纸条像是一组，就把它们放进同一个盒子里。
这个盒子就是树里的一个节点。

→

第 3 步

给每个盒子算一个“大概意思”。
也就是：这盒内容大概在讲什么。

→

第 4 步

用户来提一个问题。
系统先看看这个问题大概像什么。

第 5 步

拿这个问题去和每个盒子比。
看哪个盒子最像这个问题。

→

第 6 步

如果大盒子不够准，就继续打开它，往下看更小的盒子。
这就是树检索。

→

第 7 步

找到最像的盒子以后，把它里面对应的原文片段找出来还给你。

→

最终结果

你拿到的不是空标签，而是：
和问题最相关的原文内容。

补充：
不用 LLM 也能跑。
只是不用 LLM 时，系统更多靠文档本身的结构和位置来分盒子，所以有时候会分得比较粗。

如果加上 LLM，通常能更像人类理解的“目录树”那样去分，但也会更依赖模型和配置。
