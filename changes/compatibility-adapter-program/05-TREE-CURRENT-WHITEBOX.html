当前 Tree 主线白盒流程

这张图只描述当前默认 tree 主线：文档 → spans → persisted tree → vector chunks → tree 内部语义统计 → traversal + decision → tree hits。 它回答的是“现在系统默认怎么生成树、怎么检索树、哪些 donor 逻辑已经被吸收”。

1. 从文档到 persisted tree

原始文档

PDF / DOCX 文件保留在文件系统；数据库只登记 source_uri、content_hash、version。

→

register_document

生成 doc_id / version_id，写入 documents / document_versions。

→

canonical_spans

Docling 解析后的最小证据单元。后续所有 tree / vector / graph 都围绕 span_id 展开。

→

TreeGenerator

按 heading_path 组装 persisted tree，并在同 heading 下做轻量 semantic split。

→

tree_nodes / tree_node_spans

树节点持久化，以及 node ↔ span 的精确映射。

关键代码 - ingestion/pipeline.py → IngestionPipeline.ingest() - registry/tree_generator.py → generate_tree() - registry/postgres_adapter.py → write_tree()

2. 从 spans 到 chunk embeddings

canonical_spans

读取当前 version 的 spans，保证 start/end offset、heading_path、raw_text 已落库。

→

VectorLoader

切 chunk、写 vector_chunk_spans、计算 embedding，并可投影到 pgvector / Qdrant / Milvus。

→

vector_chunks

每个 chunk 带 text_preview / heading_path / embedding / node_id。

→

chunk → node 回链

通过 vector_chunk_spans + tree_node_spans，把 chunk embedding 归属到 tree node。

关键代码 - vector/loader.py → load() - vector/loader.py → _link_tree_nodes() / _repair_tree_nodes() - registry/postgres_adapter.py → query_vector_chunks_by_version() / query_vector_chunk_spans_by_version()

3. Tree 内部语义统计（当前默认主线）

TreeSemanticDistributionAdapter

把 vector chunks 的 embedding 聚到 tree nodes 上，产出 node 级语义统计，而不是直接召回答案。

centroid
dispersion
entropy
support_count
llamaindex_runtime/tree/semantic_distribution.py - PersistedTreeSemanticDistributionAdapter - _collect_chunk_assignments() - _compute_centroid() - _compute_entropy()

借来的 donor 思想

当前默认并不是 donor 原仓直接跑，而是吸收 donor 的局部强逻辑。

来自 Psi-RAG： - prototype embedding 思路 - traversal skeleton 思路 来自本地： - dispersion - entropy - support_count - provenance-preserving node/chunk/span 聚合

4. Tree retrieval：从 query 到 tree hit

query(mode="tree")

统一入口；给 registry + version_id 时走 persisted tree backend path。

→

query embedding

如果提供 embed_model，则先将 query 转为 embedding，用于 node 级语义比对。

→

semantic distribution

读取 node stats，优先使用 prototype embedding / centroid 做 query-to-node 相似度。

→

traversal runner

从 root 开始，逐层决定 keep_parent / drill_down / prune。

→

decision policy

默认 baseline；显式切换时可使用 HIRO policy。

→

BackendHit / QueryHit

输出 node_id、span_ids、heading_path、text_preview、score。

关键代码 - tree/runtime.py → _retrieve_tree_hits_from_backend() - tree/semantic_distribution.py → RecursiveTreeTraversalRunner - tree/semantic_distribution.py → BaselineTreeBranchDecisionPolicy - tree/hiro_decision_policy.py → HIROEnhancedTreeBranchDecisionPolicy

5. 当前默认 vs 可选 donor path

默认主线

  • 本地 persisted tree
  • 本地 semantic-distribution statistics
  • Psi-RAG donor 思想吸收到 traversal / prototype 表示
  • 默认 decision policy = baseline

已接入但非默认

  • PageIndexTreeAdapter
  • HIROEnhancedTreeBranchDecisionPolicy（显式切换）
意思： - 代码里有 - 可显式调用 - 但默认不会自动走

还只是研究/参考

  • RAPTOR（结构 donor 参考）
  • LightRAG（graph 支线暂停）
  • RAG-Anything（multimodal 支线暂停）

6. LLM 到底是不是必须？

当前默认 baseline tree

不必须。 当前 persisted tree + vector stats + traversal 主线没有 LLM 也能生成树并检索。

PageIndex donor structural tree

通常需要。 尤其是 TOC / structural extraction 这条 donor 路径，在真实文档上更依赖统一 LLM seam。
