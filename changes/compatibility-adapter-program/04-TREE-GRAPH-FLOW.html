Tree / Graph Whitebox Flow

这份 HTML 把当前项目里“文档 → spans → tree → vector → graph → retrieval”的主链路画成白盒流程图。 它描述的是当前 E:\github\rag 里的真实实现，而不是理想化架构图。

Registry / Provenance Tree Vector Graph

1. 存储主链

原始文档

PDF / DOCX 文件仍在文件系统，数据库只登记其来源与版本。

→

register_document

生成 doc_id / version_id，记录 content_hash、source_uri、processing_status。

→

canonical_spans

Docling 解析后写入标准化 spans，span_id 是后续所有回溯锚点。

→

tree_nodes / tree_node_spans

按 heading_path + 轻量 semantic split 长出 persisted tree，并把 span 绑到 node。

→

vector_chunks / embeddings

chunk 生成、embedding 计算、chunk↔span 持久化，可选投影到 Qdrant / Milvus / pgvector。

→

entities / evidence_links / Neo4j

当前默认图谱抽取为 heuristic；后续可由 donor graph 路线替换内部逻辑。

2. Tree 生成流程

当前默认 persisted tree

  1. 读取 canonical_spans
  2. 按 heading_path 组织父节点
  3. 同 heading 下做轻量 semantic cluster
  4. 写入 tree_nodes 与 tree_node_spans
E:\github\rag\llamaindex_runtime\registry\tree_generator.py - _group_spans_by_heading_path() - _build_parent_nodes() - _append_leaf_nodes() - generate_tree()

PageIndex donor path（可选）

  1. 调用 PageIndex tree parser
  2. TOC / structure detection 走统一 LLM seam
  3. embedded tree flatten 成本地 flat node
  4. 写回本地 registry，保住 node_id / span_id 链
E:\github\rag\llamaindex_runtime\tree\pageindex_adapter.py - index_tree() - _call_pageindex_tree_parser_stub() - _flatten_embedded_tree()

3. Tree 内部语义分布链

vector_chunks

每个 chunk 有 embedding，并通过 chunk↔span 映射可回到 span。

→

node ↔ span

通过 tree_node_spans 把 span 聚到 node，再把 chunk embedding 归属到 node。

→

TreeSemanticDistributionAdapter

为每个 node 产出 centroid / dispersion / entropy / support_count。

→

Decision Policy

当前默认 baseline；可显式切到 HIRO policy，决定 keep_parent / drill_down / prune。

Baseline 统计层

llamaindex_runtime/tree/semantic_distribution.py - PersistedTreeSemanticDistributionAdapter - _compute_centroid() - _compute_entropy() - _collect_chunk_assignments()

Traversal 层

llamaindex_runtime/tree/semantic_distribution.py - RecursiveTreeTraversalRunner - traverse_tree_for_query() - _traverse_from_node()

Decision 层

默认：BaselineTreeBranchDecisionPolicy 可选：HIROEnhancedTreeBranchDecisionPolicy runtime 开关：tree/runtime.py parameter: decision_policy="baseline" | "hiro"

4. Tree 检索流程

query(mode="tree")

统一入口；给了 registry + version_id 时走 persisted tree backend path。

→

_retrieve_tree_hits_from_backend

取树节点、取 query embedding、跑 semantic distribution + traversal。

→

QueryHit / BackendHit

输出 node 命中，并附带 provenance：node_id、span_ids、heading_path、score。

E:\github\rag\llamaindex_runtime\tree\runtime.py - _retrieve_tree_hits_from_backend() - retrieve_tree_hits_from_pdf()

5. 当前图谱生成与检索流程

tree_nodes + summaries

当前默认 graph 抽取不是 LLM donor，而是从 tree node 的 title / heading_path / summary_text 推实体名。

→

entities / node_entity_links / evidence_links

写回本地 registry，证据仍然锚在 span_id 上。

→

Neo4j projection

project_version_to_graph() 把实体/关系/证据投影到 Neo4j。

→

graph query

给 entity_id，查邻居，返回 QueryHit。

6. 当前主线 vs 可选路径

当前默认主线

  • 本地 registry / provenance contracts
  • persisted tree backend
  • 本地 semantic distribution baseline
  • 默认 baseline decision policy
  • 本地 heuristic graph extraction

当前已接入但非默认

  • PageIndexTreeAdapter（tree build / retrieve donor）
  • HIROEnhancedTreeBranchDecisionPolicy（显式切换）
  • 统一 LLM seam（donor-facing structural extraction）

当前只研究未接入

  • RAPTOR（structure donor reference）
  • LightRAG（graph 支线暂停）
  • RAG-Anything（multimodal 支线暂停）
  • Yuxi（不推荐作为 runtime donor）
