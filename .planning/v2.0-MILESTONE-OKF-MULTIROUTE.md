## 4. 流程定义（七条核心流，跨阶段共享语言）

**F1 入库流（Phase 14 建、15 唯一化）**
`二进制(PDF/Word) → docling → NormalizationContract.normalize()（span_id 六要素在此定型） → docling→OKF serializer → raw/*.md（人类可读，机器生成） + *.spans.json sidecar（span 身份唯一来源） → OKF parser → PostgreSQL 派生表`

**F2 E1 重建流（Phase 14 建 canonical-span reconciliation）**
`已注册的 documents/document_versions provenance parents + admitted raw OKF frontmatter/sidecar → rebuild-from-okf 脚本 → 确定性协调 canonical_spans → S_okf 与 S_direct 比对 → transaction/audit 与 okf_rebuild_log 记录 → 第二次等价运行零 canonical-span DML`
**边界：** E1 不 drop/rebuild parents、vector chunks、tree nodes、entities、relations、evidence 或 NER associations；FK cascade cleanup 不是 reconstruction。E2a 与 E2b 共同承担完整 derived-association parity。

**F3 同步流（Phase 14 建增量机制、15 接管全量）**
`OKF 文件变更 → canonical structural hash 比对（T3；格式化重写不触发重建） → 增量 upsert / 删除检测 → okf_sync_state 更新`

**F4 检索流（Phase 17 扩到四路）**
`query → R1 / R2a / R2b / R3 并行 → analysis/fusion.py::fuse_candidates（RRF + 来源标签；T7：R3 只进此路径） → 证据输出（canonical_spans 坐标）`

R3 的 query-side 实体种子识别必须复用同一已启用的 C1 `EntityExtractor` adapter、版本化 label map 与 `MentionCandidate` 输出契约，但通过判别联合的 `QueryTextInput` 变体调用；首期仍采用 RaNER 的 `type/start/end/span` 映射、字符切片校验、`confidence=None` / `confidence_kind="unavailable"` 语义及模型/artifact provenance。`QueryTextInput` 复用 normalized-text Unicode code-point 坐标、normalization/segmentation 版本和 label-map digest，只携带 query-local immutable identity，输出 `input_revision=query_revision`、没有 corpus `span_id`/document projection；candidate/pre-merge/merger artifact 严格 request-scoped，禁止进入任何 durable audit/mention/merge/alias/link/corpus-evidence store。Phase 17 不得另造 query-only NER adapter、坐标或 provenance 契约，也不得伪造 corpus document 坐标。开关依赖固定 fail-closed：`RAG_ROUTE_R3=on` 只允许与 `RAG_ENTITY_EXTRACTOR=raner` 组合；`on/off` 必须启动时报配置错误，不得自动加载模型、纯词典降级或伪装为空路。

**F5 回写流（Phase 18 建）**
`Agent 提案 → staging 区（不落 OKF 正文） → 人工审阅 → 合入 OKF → 走 F3 同步流入库`

**F6 评估流（Phase 19 建，D4 冻结中）**
`固定查询集 → 四路/消融矩阵运行 → 人工判定 → 指标 vs 冻结阈值（hit_rate ≥0.80 / top1 ≥0.90 / stability ≥0.85） → 权重/开关决策`

**F7 试点流（Phase 20 建，三重门后）**
`试点 corpus P0（S_direct == S_okf） → 派生层全量重建（P1） → 权限/隔离在候选生成层生效 → 可观测试运行（P2） → 真实规模回滚演练（P3） → G5 试点价值评估（输入自 Phase 19） → G6 Go/No-Go（人类签署）`

## 5. 跨阶段边界裁决（提前画死，避免执行期扯皮）

3. **16/17 边界**：16 只产数据（entity_mentions/aliases/links），不碰检索；17 只消费数据接融合，不回头改抽取器。
4. **17 内部红线**：R3 只进 `fuse_candidates`（RRF）；`_compute_fusion_score` 固定权重（0.40/0.30/0.20/0.10，和为 1）不动；`_fuse_candidate_scores` 不存在于代码库，任何计划引用它即作废。
