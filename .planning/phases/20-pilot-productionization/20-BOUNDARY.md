# Phase 20 (交接书阶段 G): Restricted Business Pilot & Production Readiness — Boundary Document

**Drawn:** 2026-07-12（规划级新增，plan-everything-execute-nothing 指令下的预规划产物）
**Depth:** 边界级。进入 PLAN 时由 `/gsd-plan-phase 20` 细化——本文件即其输入。
**Authority:** 补充交接书 `.planning/OKF-LOW-TOKEN-GAPS-SUPPLEMENT-HANDOFF-2026-07-12.md` §5 + 交接书 §11-G + DOCX 路线图阶段 6 + 里程碑边界裁决 10 + D1/D8/T8。
**性质声明：** 本文件是纯规划产物。**无任何执行授权**——不部署、不建库、不改代码、不动 OKF bundle。

## Entry Gate（三重门，缺一不可）

1. **质量门**：D4 已由用户明确解冻，且 Phase 19 关闭（G3/G4/G5 裁决记录齐备）。
2. **授权门**：用户对试点的**独立明确授权**——Phase 19 通过或 G5 结论积极都不自动构成试点授权。
3. **corpus 一致性门（试点 P0 前置）**：在真实试点语料上重跑 `S_direct == S_okf` round-trip 同一性验证；试点语料必须与 Phase 19 评测语料同版本，否则 G5 结论对试点无效。

## Goal

在**单一受控业务知识库**上试点整套 OKF SSOT + 四路检索架构，并建立生产就绪基线：数据治理、权限/隔离、索引运维、可观测性、灰度/回退、人工反馈闭环、运维与安全。以 G6（Go/No-Go，人类签署）收束——本阶段回答"这套架构能不能安全地服务真实业务"，不回答"要不要推广到多库"（那是 v3.0 级问题）。

## In Scope（能力域）

- **数据治理**：试点语料的接入审批、来源登记、版本与 checksum 管理（沿用 F1/F3 流，不新建平行链）。
- **权限/隔离**：corpus 级访问控制**在候选生成层强制**（检索 SQL / 召回入口带 scope 过滤），不是 UI 层过滤结果；四路（R1/R2a/R2b/R3）一致生效（Phase 17 已预留接口位——见 17-BOUNDARY Open Question 5）。
- **索引运维**：全量重建/增量同步的运维手册化（触发条件、耗时预算、失败处置）；派生表索引健康检查。
- **可观测性**：检索延迟/召回量/路由分布/错误率的指标与日志，**监控本身不依赖 LLM**；P95 延迟作观测指标记录（DOCX"P95 ≤ 5s"是源头级目标线，不是 G6 硬性承诺）。
- **灰度/回退**：试点用户分批放量；每个放量步骤有回退动作；**P3 真实规模回滚演练**——在试点规模上实际执行"删除派生层→仅凭 OKF 重建→校验通过"，这是 D1"派生层可重建"主张唯一的真实规模证明。
- **人工反馈闭环**：试点用户反馈经 Phase 18 的 proposal/staging 通道进入知识修正流程（人审框架 T8 不变）。
- **运维与安全基线**：凭据管理（`DATABASE_URL` 等不进任何产物）、备份/恢复（OKF Git 即备份权威）、依赖与补丁基线。

## Out of Scope（画死）

- **多业务库推广**：只做单一受控库；多租户、多库路由是明确的非目标。
- **Agent 回写默认开启**：试点中 Agent 回写**默认关闭**；启用 proposal 流程需要**第四个独立授权**（在三重门之外单独请求），且 T8 人审框架不变、无自动 commit。
- **新检索能力开发**：四路架构在 19 已定型；试点期发现的功能缺陷走缺陷流程或 roadmap evolution，不在本阶段顺手加功能。
- **质量调参**：权重/开关的裁决权在 Phase 19；试点期只观测不调参（发现严重回退走回退动作，不现场调优）。
- **SLA 承诺**："P95 ≤ 5s"等指标只记录不承诺；正式 SLA 属 G6 通过后的运营决策。

## Deliverables（PLAN 时映射为 waves）

1. 试点 corpus 接入与 P0 验证（round-trip 同一性 + 版本对齐证明）。
2. 权限/隔离实现（候选生成层 scope 强制 + 四路一致性测试 + 越权访问回归）。
3. 运维手册 + 可观测性面板（无 LLM 依赖监控）。
4. P1/P2 验证产物（派生层全量重建证明；可观测试运行记录）。
5. **P3 回滚演练报告**（真实规模删除→重建→校验的完整记录，含耗时与偏差）。
6. G6 决策包：G5（来自 Phase 19）+ P0-P3 证据 + 风险清单 → 人类签署 Go/No-Go。
7. 20-VERIFICATION：R-OKF-10 goal-backward。

## Draft Acceptance Criteria

- **P0**：试点语料 `S_direct == S_okf` 100% 通过。
- **P1**：派生层可仅凭 OKF bundle 全量重建，重建后检索输出与重建前一致。
- **P2**：试运行期间指标/日志完整可查，无监控盲区。
- **P3**：真实规模回滚演练通过——演练报告是 D1 主张的收官证据。
- 权限/隔离：越权查询在候选生成层即返回空/拒绝（不是结果过滤后为空）；四路行为一致。
- **G6**：Go/No-Go 由人类签署，决策依据（G5 + P0-P3）全部可追溯。
- Agent 回写全程保持默认关闭（除非第四授权已单独取得并记录）。

## Open Questions（进 PLAN 时必须先答）

1. 试点业务库的选定与语料授权：哪个业务域？语料的合规/授权状态？（用户决策，规划不预设）
2. scope 过滤的实现层：DB 行级（corpus_id 列 + 查询谓词）还是应用层召回入口？（倾向 DB 谓词——四路一致性更易证明）
3. 试点用户群与放量节奏：几批？每批规模？回退触发指标定什么阈值？
4. P3 演练窗口：在线演练（影子重建后切换）还是维护窗口停机演练？（影响运维手册设计）
5. 可观测性栈选型：复用现有日志设施还是引入轻量指标组件？（约束：不引入 LLM 依赖、不引入重型新基础设施）

## Risks

| 风险 | 缓解 |
|---|---|
| 试点语料与评测语料版本漂移，G5 结论失效 | 入口门 3 强制同版本；版本对齐证明进 G6 决策包 |
| 权限过滤做成 UI 层结果过滤（隔离假象） | 边界明写"候选生成层强制"；越权回归测试在验收标准里 fail-closed |
| P3 演练在真实规模上失败（重建超时/偏差） | P1 先在试点规模全量重建演练；失败即 No-Go 输入，不带病上线 |
| 试点期"顺手调参/加功能"侵蚀 19 的裁决 | Out of Scope 画死；变更一律走缺陷流程或 roadmap evolution |
| Agent 回写被隐式打开 | 默认关闭 + 第四独立授权要求 + 验收标准显式检查 |
