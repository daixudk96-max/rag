## 1. 生产流程图 (定稿, 用户批准版)

```
新一批文章来了
   │
   ▼
先拿一小撮 (3~5 篇) 请 LLM 试抽, 一次回答两个问题:
   ① 老单子够不够用? (单子管不着的新内容)
   ② 这批文章彼此像不像? (结构一致 or 大杂烩)
   │
   ├─ 情况 A 相似批: 人确认补栏 → 单子冻结 → UIE 机器全批抽 (0 LLM)
   │
   └─ 情况 B 大杂烩批: 纯 LLM 逐篇抽 (按老单子+报告新类型, 禁自由发挥)
         └─ 兼作单子采矿机: 新类型攒多确认后, 以后相似批转 UIE
   │
   ▼ 两路汇入同一下游:
归一化 (三出口) → 可疑的进篮子 (带原句) → LLM 核对 (只核对不重抽) → 入库 LightRAG
```

无'眼熟分类器' (用户否决: 判断不可靠); 分流由试抽本身完成。

## 2. Schema (单子) 生命周期

- 状态机: `proposed (LLM 试抽提议)` → `confirmed (人拍板)` → `active (批次内冻结)` → `retired (可选)`。
- 每条带 provenance: 谁提议 (哪次试抽/哪批大杂烩报告)、人何时确认、适用哪些货源。
- 批次运行期间单子冻结, 防中途换尺; 新类型走下一批次。

## 3. 复核篮子规则

- 每条三元组强制带出处 (source span/原句), 无出处不入库。
- 篮子复核 = 核对 (原句是否支持该三元组), **禁止开放式重抽** (防 LLM 顺手脑补)。
- 三出口: AUTO (核对过+高置信直入) / REVIEW (人审篮) / NEW (升级为新类型提议, 回流单子生命周期)。

## 11. D2 修订 v2 — 试抽分流制加量化覆盖门 (2026-09-01 用户修正, 推翻 §1 中'老单子基本够'分支)

用户原话要点: '不能有纯的uie'; '一批…文件结构相似也要llm试抽加uie'; '一批不同直接llm为主加uie辅助抽取'; '老单子基本够这种无法量化怎么确定呢 除非能先用llm判定老单子能抽百分之90才能纯uie'。

**修正理由 (采纳)**: 原流程'结构相似→老单子够→直接纯 UIE'中, '老单子够'无法量化, 等于凭感觉放行, 会静默漏抽。

### v2 流程 (取代 §1 图中分流规则; 无分类器、每批必经 LLM 试抽)
```
新一批文章 → LLM 试抽 (每批必经, 3~5 篇):
   按老单子抽样本 + 量化判定: 样本里的事实, 老单子能覆盖百分之几? 覆盖不了的是什么?
   │
   ├─ 覆盖率 >= 阈值(默认 0.90, 可配置) 且结构相似 → 允许纯 UIE 全批 (0 LLM);
   │     样本中未覆盖的 ~10% → 新类型提议 → 人确认 → 单子生长 (下一批生效)
   ├─ 覆盖率 < 阈值 且结构相似 → LLM 试抽补全单子 (人确认新栏) → UIE 全批 (用扩展后单子)
   └─ 大杂烩 (逐篇不同) → LLM 为主逐篇抽 (单子内项也由 LLM 抽 + 报新类型), UIE 辅助
         (UIE 先扫单子内常见项给 LLM 对表/交叉核对, 分歧进篮子)
   │
   ▼ 归一 → 篮子 (带原句核对) → 入库
```

### v2 硬规则
- **纯 UIE 不是默认路径, 是奖励路径**: 仅当试抽报告量化判定覆盖率 >= COVERAGE_THRESHOLD (常量, 默认 0.90, 进 schema/config) 时才准入。
- 试抽报告强制落盘 (批次证据): 样本量/覆盖率数字/未覆盖清单/路由决定 — 无报告不得全批抽取。
- 覆盖率判定由 LLM 给出、可复核 (样本事实清单 + 逐条标注 可抽/不可抽), 人在报告上可推翻。
- 大杂烩批 UIE 辅助语义: 单子内项 UIE 先扫 + LLM 逐篇抽并交叉核对; UIE 有 LLM 无 → 补录; LLM 有 UIE 无 → 保留 (LLM 为准) 并记分歧。
- 影响: W3 计划按 v2 重写 (覆盖率判定 + 阈值门 + 三路由); W2 适配器不受影响 (只管翻译不管分流), 继续执行。
