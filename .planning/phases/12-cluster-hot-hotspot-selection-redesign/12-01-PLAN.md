<objective>
Close the E2 data gap so the hybrid_cluster selector can compute a true direct-child coverage denominator. Today `HotspotSelectionContext` only carries `node_stats`, which `_build_node_stats` populates only for nodes with direct/subtree vectors (`if not vectors: continue`, semantic_distribution.py:243). A parent's no-vector children are therefore invisible, making real coverage uncomputable. This plan adds a `parent_to_children` denominator built from the COMPLETE `tree_nodes` and threads it into the selection context — without changing any scoring behavior yet.

Purpose: Establishes the data prerequisite for the cluster-hot coverage rule (D-01/D-02). No selection logic changes in this plan.
Output: Extended `HotspotSelectionContext`, a `parent_to_children` key in the distribution report, runtime wiring in the hybrid_cluster branch, and RED-then-GREEN tests for the context contract.

NOTE: This plan is `autonomous: false` because Task 1 is a `checkpoint:manual` GitNexus impact-analysis gate (no CLI/API equivalent; runs via the GitNexus MCP, paused for the operator to record the blast radius).
</objective>
