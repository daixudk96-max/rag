<objective>
Prove and repair the ingestion materialization gap: determine whether `VectorLoader.load()` is invoked for the active version, make its invocation explicit and idempotent where appropriate, and document the authoritative `heading_path` storage contract used by metrics.
</objective>

<must_haves>
  <truths>
    <truth>Vector chunk materialization is an explicit, testable step after canonical spans exist.</truth>
    <truth>`VectorLoader.load(conn, version_id)` remains idempotent and safe to rerun for partial states.</truth>
    <truth>`canonical_spans.heading_path` is treated as authoritative for heading-path completeness unless this plan explicitly proves a different contract.</truth>
    <truth>Human judgment collection remains blocked if materialization cannot produce explainable non-zero chunk/mapping metrics.</truth>
  </truths>

<threat_model>
  <threat id="T-05-04" severity="medium" stride="Tampering">
    Running vector materialization against the wrong active version could mutate or repair the wrong version's chunks.
    Mitigation: require explicit `--version-id` or latest active version resolution in one place, print selected version_id, and use parameterized queries.
  </threat>
  <threat id="T-05-05" severity="low" stride="Denial of Service">
    Re-running materialization with real embeddings/vector backend could be expensive.
    Mitigation: default to deterministic local `VectorLoader(embed_dim=16)` for verification and make external vector projection opt-in.
  </threat>
</threat_model>
