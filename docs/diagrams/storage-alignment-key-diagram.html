三库对齐主键关系图

目标：让 KG / Vec / Tree 三层各自按最适合自己的方式存储，但通过统一身份层和版本层保持稳定对齐。

核心原则：不要统一 chunk，要统一 doc_id / version_id / span_id 这套身份与版本坐标。

1. 总体主键关系图

PostgreSQL registry 做事实层；Neo4j 做图视图；Milvus/Qdrant 做向量视图；Tree/docstore 做层级视图。

flowchart LR subgraph Registry[PostgreSQL Registry / Mapping Layer] D[documents\ndoc_id] V[document_versions\nversion_id\ncontent_hash] S[canonical_spans\nspan_id\nstart_offset/end_offset] N[tree_nodes\nnode_id\nparent_node_id\nheading_path\npage_no] C[vector_chunks\nchunk_id\nnode_id\nspan_ids] E[evidence_links\nentity_id/relation_id\nspan_id] end subgraph Graph[Neo4j KG Layer] G1[(Entity Nodes\nentity_id)] G2[(Relation Edges\nrelation_id)] G3[(Evidence Edges\nversion_id + span_id refs)] end subgraph Vector[Milvus / Qdrant] V1[(Embedding Records\nchunk_id\ndoc_id\nversion_id\nnode_id\nentity_ids[])] end subgraph Tree[Tree / Docstore Layer] T1[(Hierarchy Nodes\nnode_id\nparent_id\nchild_ids)] end D --> V --> S V --> N S --> N S --> C S --> E N --> C E --> G1 E --> G2 E --> G3 C --> V1 N --> T1 C -.回映.-> T1 G3 -.证据定位.-> S V1 -.命中后回映.-> C

2. 更新顺序图

关键是版本化写入，不做原地重写；新版本校验通过后，再切 active version / alias。

flowchart TD A[原始文档] --> B[写 documents] B --> C[写 document_versions\nversion_id / content_hash] C --> D[生成 canonical_spans] D --> E[派生 tree_nodes] D --> F[派生 vector_chunks] E --> G[写 Tree / Docstore] F --> H[写 Vector DB] D --> I[跑图谱抽取] I --> J[写 KG 实体 / 关系] J --> K[写 evidence_links] G --> L[端到端校验] H --> L K --> L L --> M{校验通过?} M -->|是| N[切 active version / alias] M -->|否| O[废弃新版本并回滚] N --> P[回收旧版本数据]

3. 查询回链图

复杂查询时，KG / Vec / Tree 三层通过统一 ID 和 span 关系串起来。

flowchart TD Q[用户问题] --> A1[KG 查询] A1 --> A2[得到 entity_ids / relation_ids] A2 --> B1[通过 registry 找到相关 span_id / chunk_id] B1 --> B2[向量库中受约束检索] B2 --> B3[返回命中 chunk_id] B3 --> C1[回映到 node_id] C1 --> C2[向上找 parent_id / sibling nodes] C2 --> C3[命中分布分析 + 扩展决策] C3 --> OUT[统一结果输出]

推荐统一的东西

  • doc_id：文档身份
  • version_id / content_hash：版本身份
  • span_id：规范证据坐标
  • 映射与 provenance 关系

不推荐硬统一的东西

  • 向量 chunk 的切法
  • 树节点的切法
  • 图谱证据跨度

最容易出错的点

  • 把 chunk_id 当成全局主身份
  • 没有 version_id 就直接覆盖写入
  • 图谱证据强行贴合向量 chunk 边界
工程建议：采用“一个 canonical span 标准 + 多个派生切片标准”的架构： 向量层按 embedding 友好切，树层按结构友好切，图谱层按证据友好切；三者通过 registry 的 span_id 稳定对齐。
