LlamaIndex 作为 Tool / 子模块的集成架构图

把 LlamaIndex 作为内部检索与决策层，对外包装成 Tool，供 LangChain / langclaw / Claude / 其他 Agent 调用。

一句话：外部 Agent 不负责复杂检索逻辑；它们只调用 Tool。真正的 Vector / Graph / Deep Hybrid 路由，都在 LlamaIndex 内部完成。

1. 总架构图

外部 Agent 只看到 Tool，内部由 LlamaIndex 做路由与结果组装。

flowchart LR U[用户问题] --> A[外部 Agent / 编排层] A --> B[Tool 调用层] subgraph External[外部系统] A1[LangChain Agent] A2[langclaw] A3[Claude / 其他 Agent] end A --> A1 A --> A2 A --> A3 B --> T1[knowledge_router_tool] B --> T2[vector_search_tool 可选] B --> T3[graph_reasoning_tool 可选] B --> T4[deep_hybrid_tool 可选] subgraph Internal[LlamaIndex 内部能力层] R[查询分类 / 路由器] V[轻量路径 Vector Path] G[概念路径 Graph Path] H[复杂路径 Deep Hybrid Path] O[统一结果组装器] end T1 --> R T2 --> V T3 --> G T4 --> H R --> V R --> G R --> H V --> O G --> O H --> O O --> B B --> A A --> U

三类问题走三条路径：轻量向量、概念图谱、复杂混合。

建议你怎么用：
  • 优先对外只暴露一个总工具：knowledge_router_tool
  • 内部再拆成三条路径：vector_path / graph_path / deep_hybrid_path
  • 这样外部 Agent 最简单，内部能力最可控，后续替换逻辑也不影响对外接口。
