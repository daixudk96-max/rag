最终架构图：Provenance-Centric Multi-View RAG

目标：构建一个统一身份层、版本层、证据层的多视图 RAG 内核，内部支持 Keyword / Vector / Graph / Deep Hybrid 四条路径，对外暴露成 Tool / API / CLI。

一句话总结： 不要统一 chunk，要统一 doc_id / version_id / span_id； 不要统一三层结构，要统一身份、版本和证据回链。

1. 最终系统总图

原文只解析一次，先进入统一的 provenance / registry 层，再派生为 Keyword / Vector / Tree / Graph 多视图，由 LlamaIndex 编排查询路径。

2. 四条查询路径

系统不是一个检索器，而是一个内部有四种检索逻辑的 Router。不同问题走不同路径。

flowchart TD Q[用户问题] --> C[Query Classifier] C -->|精确术语 / 指标 / 节目名 / 标准号| K1[Keyword Path] C -->|轻量语义问题| V1[Vector Path] C -->|概念 / 实体 / 关系问题| G1[Graph Path] C -->|复杂跨章节 / 多跳推理| H1[Deep Hybrid Path] subgraph KeywordPath[Keyword Path] K1 --> K2[PostgreSQL FTS / trigram / BM25] K2 --> K3[返回 span / chunk / node] end subgraph VectorPath[Vector Path] V1 --> V2[VectorStoreIndex] V2 --> V3[返回 semantic chunks + parent context] end subgraph GraphPath[Graph Path] G1 --> G2[PropertyGraphIndex / Neo4j] G2 --> G3[返回 entities / relations / evidence] end subgraph HybridPath[Deep Hybrid Path] H1 --> H2[KG 先锁定概念与关系] H2 --> H3[registry 找相关 span_id / chunk_id / node_id] H3 --> H4[受约束关键词 / 向量检索] H4 --> H5[树层级回并] H5 --> H6[命中分布分析] H6 --> H7[父节点 / 兄弟节点 / 相邻块扩展] H7 --> H8[重排 + 统一答案生成] end K3 --> OUT[统一结果输出] V3 --> OUT G3 --> OUT H8 --> OUT

3. 数据更新与版本切换图

重点不是“原地更新”，而是“新版本写入 → 校验 → 切 active version / alias → 回收旧版本”。

flowchart TD A[原始文档变化] --> B[生成新 version_id] B --> C[按当前 normalization contract 重新解析] C --> D[生成 canonical spans] D --> E[派生 tree nodes] D --> F[派生 vector chunks] D --> G[抽 graph evidence spans] E --> H[写 PostgreSQL registry] F --> H G --> H H --> I[写 Keyword View] H --> J[写 Vector View] H --> K[写 Tree View] H --> L[写 Graph View] I --> M[一致性校验] J --> M K --> M L --> M M --> N{校验通过?} N -->|是| O[切 active version / alias] N -->|否| P[回滚并保留旧版本] O --> Q[回收旧版本投影视图]

最终使用的项目

  • LlamaIndex：内部大脑、查询路由、四路径编排
  • PostgreSQL：registry / provenance / versioning / keyword path
  • Neo4j：知识图谱执行层
  • Milvus / Qdrant：向量执行层
  • Docling：一次解析层

对外暴露成什么

  • knowledge_router_tool
  • API：/query
  • CLI：knowledge-router
  • 也可接入 LangChain / langclaw / Claude

最关键原则

  • 原文只解析一次
  • 统一的是 span_id，不是 chunk
  • 图 / 向量 / 树都是 derived views
  • 重切片按 version 更新，不原地覆盖
