## 架构对比：两条路径

### 路径A：Vector Backend → TreeGenerator → Tree

```
流程：
  PDF/Markdown → Chunking → Spans → TreeGenerator → Tree nodes

特点：
  - 先chunking（vector backend）
  - 然后生成spans（span indexer）
  - 最后TreeGenerator从spans推导树
  - 适合：vector检索场景

用途：
  - VectorBackendAdapter依赖
  - Hybrid retrieval（vector + tree）
```

### 路径B：PageIndex Backend → 直接树

```
流程：
  PDF/Markdown → PageIndexTreeAdapter → Tree nodes

特点：
  - 直接提取树结构（不经过chunking）
  - PageIndex TOC detection
  - 适合：纯树检索场景

用途：
  - TreeBackendAdapter主路径
  - PageIndex完整功能
```

### 3. **两者并存，互补**

**对比**：

| 维度 | TreeGenerator | PageIndexTreeAdapter |
|------|---------------|---------------------|
| **树构建来源** | Spans推导 | PDF/Markdown直接 |

**并存价值**：
- ✓ 不同场景不同backend
- ✓ Hybrid检索需要两者
- ✓ 配置驱动选择
